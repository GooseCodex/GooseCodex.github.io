# Deployment Guide

## How it works

This repo has two branches that serve different purposes:

| Branch | Purpose |
|--------|---------|
| `main` | Source code — React + Vite app lives in `portfolio/` |
| `gh-pages` | Built output — raw HTML/CSS/JS served by GitHub Pages |

The deploy script builds the React app with Vite and then force-pushes the resulting `dist/` folder to the `gh-pages` branch using the `gh-pages` npm package. GitHub Pages is configured to serve from that branch, so pushing to it immediately updates the live site.

**Live URL:** https://GooseCodex.github.io

---

## Prerequisites

The `gh-pages` package is used by `npm run deploy` but is **not currently in devDependencies**. Install it once:

```bash
cd portfolio
npm install --save-dev gh-pages
```

Then commit the updated `package.json` and `package-lock.json` to `main` so you don't have to do this again.

---

## Deploy steps

```bash
# 1. Make sure you're on main and changes are committed
git status

# 2. Go into the project folder
cd portfolio

# 3. Install dependencies (if you haven't already or after a fresh clone)
npm install

# 4. Deploy
npm run deploy
```

That single command does two things automatically (via npm lifecycle hooks):

1. **`predeploy`** — runs `vite build`, which compiles the React app into `portfolio/dist/`
2. **`deploy`** — runs `gh-pages -d dist`, which takes everything in `dist/` and force-pushes it to the `gh-pages` branch on `origin`

---

## What lands on gh-pages

After a deploy, the `gh-pages` branch contains a flat structure served from `/`:

```
index.html
assets/
  index-<hash>.js
  index-<hash>.css
icon.png
profile-p.jpg
openpos_logo_v1.png
project1.gif
```

The hashed filenames are generated by Vite for cache-busting and change on every build.

---

## Things to know

- **Never commit directly to `gh-pages`.** It is fully managed by the deploy script. Any manual changes will be overwritten on the next deploy.
- **`dist/` is gitignored on `main`** — the build output never touches your source branch.
- **No `base` path needed in `vite.config.js`** — because this is a user/org GitHub Pages site (`GooseCodex.github.io`), it serves from `/` and Vite's default base is already correct. A project page (e.g. `GooseCodex.github.io/my-repo`) would need `base: '/my-repo/'`.
- **Changes on `main` are not live until you deploy.** Pushing to `main` only updates source code; you still need to run `npm run deploy` from the `portfolio/` folder.
